# 浮动助手 · 插件设计接口指南

> 版本：MVP v0.1  
> 适用：FloatingHelper.Core `net8.0-windows`  
> 最后更新：2026-09-01

## 1. 概述

浮动助手的所有动作（复制、智能打开、搜索等）均以**插件**形式提供。主程序只负责：

1. 捕获用户选中的文字；
2. 询问每个插件「你能否处理这段文字」（`CanHandle`）；
3. 把能处理的插件渲染为工具栏按钮；
4. 用户点击按钮后调用插件的 `ExecuteAsync`。

新增功能 = 新增一个实现 `IPlugin` 接口的类，无需修改主程序代码。

## 2. 核心接口

### 2.1 `IPlugin`

命名空间：`FloatingHelper.Core.Plugins`

```csharp
public interface IPlugin
{
    /// <summary>插件唯一标识，建议格式：作者域.功能名，如 "builtin.copy"。</summary>
    string Id { get; }

    /// <summary>工具栏上显示的名称，如 "复制"、"搜索"。</summary>
    string Name { get; }

    /// <summary>插件说明，显示在插件管理界面。</summary>
    string Description { get; }

    /// <summary>是否启用。由插件管理器读写，持久化到 settings.json。</summary>
    bool IsEnabled { get; set; }

    /// <summary>
    /// 判断当前选区是否可由本插件处理。
    /// 返回 true 的插件才会出现在工具栏上。
    /// </summary>
    bool CanHandle(PluginContext context);

    /// <summary>执行插件动作。主程序会捕获异常，单个插件失败不影响其他插件。</summary>
    Task ExecuteAsync(PluginContext context);
}
```

### 2.2 `PluginContext`

```csharp
public sealed class PluginContext
{
    /// <summary>用户选中的原始文本。</summary>
    public string SelectedText { get; init; } = string.Empty;

    /// <summary>选区来源进程名（可空），用于按应用过滤。</summary>
    public string? SourceProcessName { get; init; }
}
```

## 3. 插件加载机制

主程序通过 `PluginManager` 管理插件，支持三种来源：

| 来源 | 方式 | 可卸载 | 说明 |
|---|---|---|---|
| 内置插件 | 代码中 `AddBuiltin()` 注册 | 否 | 随主程序发布，如复制/智能打开/搜索 |
| 插件目录 | 启动时扫描 `{exe目录}/plugins/*.dll` | 是 | 把编译好的 DLL 丢进目录即可 |
| 手动加载 | 插件管理界面「加载外部 DLL」 | 是 | 路径记录在 settings.json，启动时自动恢复 |

所有插件的启停状态持久化到 `%AppData%\FloatingHelper\settings.json`。

## 4. 开发一个插件（5 步）

### 步骤 1：创建类库项目

```bash
dotnet new classlib -n MyPlugin -f net8.0-windows
```

在 `.csproj` 中引用 `FloatingHelper.Core`：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0-windows</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\FloatingHelper.Core\FloatingHelper.Core.csproj" />
  </ItemGroup>
</Project>
```

### 步骤 2：实现 `IPlugin`

```csharp
using FloatingHelper.Core.Plugins;

namespace MyPlugin;

public sealed class TranslatePlugin : IPlugin
{
    public string Id => "my.translate";
    public string Name => "翻译";
    public string Description => "将选中的文字翻译为中文（示例）。";
    public bool IsEnabled { get; set; } = true;

    public bool CanHandle(PluginContext context)
    {
        // 非空文本都可以翻译
        return !string.IsNullOrWhiteSpace(context.SelectedText);
    }

    public async Task ExecuteAsync(PluginContext context)
    {
        var text = context.SelectedText.Trim();
        // 调用翻译 API、打开翻译网站、写入剪贴板……
        await Task.CompletedTask;
    }
}
```

### 步骤 3：编译

```bash
dotnet build -c Release
```

产物：`bin/Release/net8.0-windows/MyPlugin.dll`

### 步骤 4：加载到浮动助手

**方式 A（推荐，自动加载）：** 把 `MyPlugin.dll` 复制到浮动助手安装目录下的 `plugins/` 文件夹，重启程序。

**方式 B（手动）：** 托盘右键 → 插件管理 → 「加载外部 DLL」，选择 `MyPlugin.dll`。

### 步骤 5：验证

- 选中任意文字，工具栏应出现「翻译」按钮；
- 插件管理界面中可看到该插件，支持启停和卸载。

### 5.1 外部插件包示例：站点直达（SiteLauncher）

仓库还附带一个**不修改主程序、可独立安装**的外部插件包 `src/FloatingHelper.Plugins.SiteLauncher/`，
用「复制 DLL 到 `plugins/` 目录」或「插件管理 → 加载外部 DLL」两种方式安装，无需改动主程序代码。

| 插件 Id | 名称 | 行为 |
|---|---|---|
| `site.search.xiaohongshu` | 小红书 | 打开小红书搜索结果页 |
| `site.search.zhihu` | 知乎 | 打开知乎搜索结果页 |
| `site.search.weibo` | 微博 | 打开微博搜索结果页 |
| `site.ask.doubao` | 豆包 | 打开豆包网页版并自动发送选中文本（官方 url-action 协议） |
| `site.ask.yuanbao` | 元宝 | 打开腾讯元宝对话页并复制选中文本到剪贴板（粘贴后发送） |
| `site.ask.deepseek` | DeepSeek | 打开 DeepSeek 对话页并带入 q 参数（配合增强脚本可自动发送） |

**安装方式：**

```bash
# 1. 构建插件包（也可直接 dotnet build 整个解决方案，构建后会自动拷入 App 的 plugins/ 目录）
dotnet build src/FloatingHelper.Plugins.SiteLauncher -c Release

# 2. 把 DLL 复制到浮动助手安装目录（或 App 输出目录）下的 plugins/ 文件夹
#    产物：src/FloatingHelper.Plugins.SiteLauncher/bin/Release/net8.0-windows/FloatingHelper.Plugins.SiteLauncher.dll
#    目标：<浮动助手目录>/plugins/FloatingHelper.Plugins.SiteLauncher.dll

# 3. 重启浮动助手，选中文字后即可看到六个新按钮
```

> 该插件包内的六个插件继承自 `UrlLaunchPluginBase`，公共逻辑（CanHandle / ExecuteAsync / BuildUrl）
> 集中在基类，子类只声明 Id、名称、图标与 URL 模板；全部为公开参数构造函数，可被
> `PluginManager.LoadFromFile` / `LoadFromDirectory` 通过反射自动实例化。
> 安装后每个插件在插件管理界面中可独立启停 / 卸载（Id 持久化在 settings.json）。

## 6. 设计约定

### 6.1 `CanHandle` 要快

`CanHandle` 在每次选区结束时同步调用，**禁止**做网络请求、磁盘 IO 或耗时计算。只做字符串判断（正则、前缀、长度）。

### 6.2 异常隔离

`ExecuteAsync` 内的异常会被主程序捕获并记录日志，但插件仍应自行处理可预期的异常（网络超时、文件不存在等），给出友好反馈。

### 6.3 不要阻塞 UI

`ExecuteAsync` 在 UI 线程调度，耗时操作必须 `await` 或放到后台线程，避免卡住工具栏。

### 6.4 Id 命名规范

- 内置：`builtin.xxx`
- 第三方：`作者标识.功能名`，如 `oldgao.translate`
- Id 一旦发布不可更改（settings.json 按 Id 持久化启停状态）

### 6.5 图标

工具栏图标由主程序按 `Id` 映射 Segoe MDL2 Assets 字符。第三方插件默认使用通用图标（`\uE71D`），后续版本将支持插件自定义图标资源。

## 7. 可用的 Core 工具类

插件可直接引用 `FloatingHelper.Core` 中的工具：

| 类 | 命名空间 | 用途 |
|---|---|---|
| `ClipboardHelper` | `FloatingHelper.Core.Actions` | 带重试的剪贴板写入 |
| `ProcessLauncher` | `FloatingHelper.Core.Actions` | 用系统默认程序打开文件/URL |
| `SearchUrlBuilder` | `FloatingHelper.Core.Actions` | 按模板构造搜索 URL |

| `Logger` | `FloatingHelper.Core.Logging` | 写入文件日志 |

## 8. 配置持久化

插件的启停状态自动持久化，无需插件自己处理。若插件需要自定义配置（如搜索插件的 `SearchTemplate`），推荐：

1. 在插件类上暴露可读写的属性；
2. 主程序启动时从 `settings.json` 读取并赋值；
3. 设置界面修改后调用保存。

具体可参考 `SearchPlugin.SearchTemplate` 的实现。

## 9. 常见问题

**Q：插件 DLL 依赖其他 NuGet 包怎么办？**  
A：把依赖 DLL 一并复制到 `plugins/` 目录，`AssemblyLoadContext` 会自动解析同目录依赖。

**Q：如何让插件只在特定应用中显示？**  
A：在 `CanHandle` 中判断 `context.SourceProcessName`，如 `return context.SourceProcessName == "chrome"`。

**Q：插件能弹出自己的窗口吗？**  
A：可以。`ExecuteAsync` 在 UI 线程，可直接 `new MyWindow().ShowDialog()`。注意 WPF 窗口需要插件项目设置 `<UseWPF>true</UseWPF>`。
